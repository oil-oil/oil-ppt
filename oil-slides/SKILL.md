# oil-slides

先确认内容，再设计页面。只判断内容、布局意图、素材和整套节奏；几何、适配、字段与构建检查交给程序。

## 设计判断

- 一页只表达一个主要判断；内容过多时删减或拆页。
- 明确演示密度：现场讲述型使用更少文字和更强视觉；独立阅读型允许更完整的信息结构。
- 根据内容选择布局权重：均衡、视觉主导、文字主导、等分或一主多辅。
- 内容少时选择更聚焦的组件，不用小字或空卡片填空间。
- 每张素材都要承担信息；对象本身可见时优先使用真实截图或真实材料。
- 标题中确有需要记住的短语时，每页最多选择一处划线强调；字段与 HTML 渲染交给 contract 和程序。
- 同时检查单页语义和整套轮廓节奏，避免连续堆叠相同构图。
- 正式预览中检查主体比例、文字分组、素材裁切和空白是否有作用。

## CLI

所有路径都相对于本 `SKILL.md` 所在目录。CLI 入口：

```text
scripts/oil-slides
```

执行时先把该相对路径解析成绝对路径；不依赖当前工作目录，不使用裸命令，不绕过入口调用内部脚本。

## 新建流程

### 1. 选择大纲协作方式

开始时先问：

> 你希望我们先通过对话一起把大纲梳理出来，还是由我根据现有材料直接生成第一版大纲？

- 选择对话时，逐步补齐目标、受众、场景、时长、已有材料和核心记忆点，并询问是否允许鼠标点击翻页。鼠标翻页默认关闭；用户没有明确选择时写为关闭。
- 选择直接生成时，只使用用户明确提供的材料，不扫描同目录、桌面或旧文件。
- 用户已经明确选择方式或提供可用大纲时，不重复询问。

### 2. 创建并确认 `outline.md`

在唯一项目根目录创建 `outline.md`。此阶段只整理内容，不选择组件，不制作预览。

大纲写清：

- 演示标题、用途、受众、场景和密度。
- 鼠标点击翻页是否开启；默认关闭。开启时左半页返回、右半页前进。
- 连续且唯一的页面编号。
- 每页标题、核心判断和支撑内容。
- 表格、步骤、引用、数据和素材需求。
- 素材展示什么，以及它回答什么问题。

只维护一份大纲。用户确认前只修改 `outline.md`；内容结构发生实质变化时重新确认。

### 3. 规划视觉

Markdown 大纲确认后，读取 `references/design-quality.md` 和 `references/media.md`，再运行：

```text
scripts/oil-slides contract
```

默认组件无法表达内容关系或需要更强媒体表现时，再运行同一入口的 `contract --all`。

根据已确认的大纲选择组件和布局权重，准备最终素材放入 `assets/`，并在同一项目根目录生成 `outline.json`。具体字段与合法选项以 contract 和程序校验为准。

需要 AI 生成概念插画时，还必须读取 `references/illustration.md`。生成插画不得包含文字；真实截图和程序化关系图按该文档的边界处理。

需要用代码绘制 UI 场景、流程、关系图或图表时，还必须读取 `references/programmatic-visuals.md`。优先生成静态 HTML/CSS 或 SVG，不把通用图表库的默认输出直接当成正式页面。

### 4. 生成正式预览

```text
scripts/oil-slides audit <项目/outline.json>
scripts/oil-slides preview <项目/outline.json>
```

根据 audit 的整套节奏建议调整 Outline 后再预览。

预览必须使用最终文案和素材。生成后停止，等待用户确认。没有明确配色时，让用户在预览中选择正式配色；写回 Outline 后重新预览。

### 5. 确认并构建

```text
scripts/oil-slides confirm <项目/outline.json> --user-confirmed
scripts/oil-slides scaffold <项目> <项目/outline.json>
scripts/oil-slides build <项目>
```

预览、Outline 或素材变化时重新预览并确认。

## 修改与交付

- 只读取用户明确指定的项目，先同步 `outline.md`，只维护当前版本。
- 最终入口固定为项目根目录的 `演示文稿.html`；交付时只指向这个文件。

故障时读取 `references/troubleshooting.md`。
