# 素材

只读取用户明确提供、附加或指向的材料；不扫描同目录、桌面或旧项目。最终素材放入项目 `assets/`，页面使用项目相对路径直接引用。

## 先决定证据，再处理文件

先说明素材展示什么、回答什么问题，再把素材放入当前页面。真实产品界面、数据、案例、人物和文档属于事实证据，必须保持保真；不让图片模型重画其中的文字、界面或数据。

### 按职责选择素材

| 画面需要表达什么 | 优先素材 | 判断边界 |
| --- | --- | --- |
| 这是谁的产品、平台或技术 | 官方 Logo 或品牌标志 | 需要识别真实对象时，不用泛化物件或生成的近似标志代替 |
| 文件、操作、状态或设备的类别 | 产品官方图标库，或一套成熟矢量图标库 | 官方图标与语义吻合时优先复用；无对应图标时选择同一体系，不混搭多套线宽与比例 |
| 产品实际界面、行为或结果 | 真实截图、文档与数据 | 图标与概念插画不能代替证据 |
| 顺序、分叉、方向、层级或数值关系 | HTML/CSS/SVG | 标签和连线保持准确、清晰、可编辑 |
| 抽象动作、取舍或协作关系 | `oil-visual` 的概念物件或场景 | 插画要显示动作与关系，不只是重复标题 |

一页可以同时使用官方标志、功能图标、插画和原生连线。先建立主次：品牌标志负责识别，插画负责理解，连线与文字负责准确关系；不要把它们排成等权的装饰图标墙。小尺寸操作符号直接用矢量图标；有明显主视觉职责的物件再考虑生成插画。

### 官方标志与风格统一

1. 从产品官网的品牌下载页、官方设计系统或官方仓库获取原文件，优先 SVG；核对当前版本、用途和许可，保存来源页。找不到可靠来源时，先用原生文字名称，不生成一个冒充官方的标志。
2. 品牌标志使用官方允许的原版、单色版或反白版，保持轮廓、比例、安全留白与规定配色。统一风格优先调整周围的色块、墨线、背景和间距。
3. 只有官方规则允许且当前任务需要时，才用 `oil-visual` 加工相关物件或装饰。官方识别标志、真实界面和信息内容保持保真；不能为了漫画风把它们重画成近似版本。功能图标的颜色与尺寸只在许可范围内统一。
4. 下载后的正式素材放入项目 `assets/`，不依赖热链或 CDN；许可、署名和修改记录按来源要求保存在项目材料说明中，需要展示的署名保留在可见位置。

页面按真实用途选择呈现方式：

- 照片和允许裁切的氛围画面可以使用 `object-fit: cover`。
- UI、文档、图表和不可裁切证据使用 `contain` 或按真实比例排版。
- 素材已经自带窗口、设备或文档边界时不再套第二层外框。
- 需要表达窗口语义且素材本身没有边界时，使用 runtime 的 `oil-browser` 或 `oil-media` 组件。
- 流程、关系、对比和数据优先使用页面内 HTML/CSS/SVG 程序化视觉。
- AI 生成只用于没有事实指向的概念插画或隐喻，图中不生成文字、数字、假 UI 或假图表。

每张图片必须有 `alt` 并使用 `../assets/...` 相对路径；装饰图使用 `alt=""`，承载信息的图片填写准确描述。程序静态检查路径、文件存在、格式头、尺寸与 `alt`；Chrome/Chromium 可用时再检查真实解码、加载和页面边界；构建时验证最终内联。AI 必须在正式预览里核对显示比例、`object-fit`、`object-position`、裁切位置和证据保真；这些语义不能交给程序猜测。

## 来源

- 用户文件、网页和产品：保留用户提供或内部使用依据。
- Wikimedia Commons：读取原始页的作者、许可和修改要求。
- Pexels：保留摄影师和来源页，遵守 Pexels License。
- Openverse：只用于发现，回原始页二次核验后才能使用。
- 普通搜索结果图不能直接进入正式预览。

获取外部图片时必须回到原始授权页。来源记录可以放在项目材料说明中，不把来源字段强塞进页面布局。
