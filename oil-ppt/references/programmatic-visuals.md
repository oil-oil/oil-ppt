# 程序化视觉

UI 场景、流程、关系、对比和数据优先使用代码绘制。目标不是画出“能看懂的框”，而是做出与幻灯片同一设计系统里的视觉证据。

## 选择方式

- **拟真 UI、工作流状态、产品操作**：优先用原生 HTML/CSS 在作者阶段绘制，再通过 `scripts/oil-ppt media render-html` 固化为无损 PNG。真实内容需要准确时使用真实截图，不仿造产品证据。
- **抽象关系、连接、结构、页面轮廓**：使用内联 SVG；复杂路径可在生成阶段使用 SVG.js，交付前导出静态 SVG。
- **小图标**：先运行 `scripts/oil-ppt icon search <语义>`，使用内置 Phosphor Regular；只在能缩短识别时间时使用。
- **真实数据图表**：优先使用 Observable Plot 生成，再导出静态 SVG 并按页面 token 调整；数据与来源必须真实。
- **快速结构草图**：可以用 Mermaid 辅助推导布局，但默认输出不能直接进入正式演示；需要重新排版、放大文字并统一配色。

最终演示不加载外部 CDN，也不在单页运行绘图库。所有库只在作者阶段使用；HTML/CSS 视觉必须经 `media render-html` 固化为 PNG，关系图和图表优先导出静态 SVG。

## PPT 级 UI 场景语法

先画一个可信的使用场景，再画细节。一个场景通常只有以下 3 层：

1. **外部语境**：浏览器、应用窗口、画布或设备，只保留一个主要外框。
2. **核心动作**：选中、移动、汇聚、切换、比较或完成；必须有明确方向。
3. **结果反馈**：一个状态变化、完成结果或焦点，不再添加第二个故事。

不要用一排同样的矩形代替 UI。至少体现真实界面的层级：顶部栏、导航、内容区、焦点对象和状态反馈；不需要表达的信息用骨架线或色块简化。

## 几何与层级

- 以 1920×1080 幻灯片为目标，视觉素材按最终占位绘制，不先做方形再裁切。
- 主体占素材面积的 55%–75%；四周保留至少 6% 安全区。
- 一个场景只用 1 个主要外框和 1 个焦点色块，不使用阴影。
- 外框圆角、边框与页面 shape profile 一致；不允许素材自带卡片壳后再放入模板卡片。
- 连接线先走水平或垂直主路径，必要时使用平滑曲线；箭头终点与目标保持 12–20 px 呼吸距离。
- 允许局部超出或错位制造层次，但不能破坏阅读方向。

## 颜色与文字

- 直接使用当前 palette 的 `canvas`、`ink`、`ink_2`、`border`、`surface`、`accent`，不自行发明另一套配色。
- 页面里已经有标题和解释时，程序图尽量无文字；用轮廓、位置、状态和高亮表达关系。
- 必须标注时，把文字放在页面原生 HTML 中；不要把正文烘焙进位图。
- 程序图内部不可避免的短标签也要满足投影下限：正文 32 px，辅助元数据 24 px；标签不超过 6 个。
- 图标只用一种风格，默认使用内置 Phosphor Regular；不混用 emoji、填充图标和不同线宽的图标。

## 让画面有趣

“有趣”来自关系和动作，不来自堆装饰：

- 用明显的前后状态、主次比例或意外但合理的空间关系建立观看兴趣。
- 让一个对象成为主角，其他对象承担上下文，不平均分配视觉重量。
- 可以用一个小的主题色块、偏移卡片、展开轨迹或局部放大制造记忆点。
- 网格、圆点和线条只用于解释对齐、范围或运动，不能只填空。

## 库的使用边界

- **SVG.js**：适合在作者阶段创建、移动和组合 SVG 元素。导出静态 SVG 后再进入项目。
- **Phosphor Regular**：使用 Skill 内置、通过程序校验的图标子集；不要从网页临时混入另一套图标。
- **Observable Plot**：适合真实数据的条形、折线、散点和小多图。关闭多余坐标轴与网格，使用页面 token。
- **Mermaid**：只做草图或复杂技术结构的初始布局。正式页面需要重新设计；不要保留默认主题、默认字体和拥挤节点。
- **D3**：只在 Plot 无法表达的定制数据关系中使用，不作为普通图表默认方案。

## 交付前检查

1. 缩小到幻灯片实际占位后，核心动作是否仍然一眼可见？
2. 去掉所有文字后，结构是否仍然大致成立？
3. 是否只有一个主要外框与一个视觉焦点，而且完全没有阴影？
4. 是否与当前页面的配色、圆角和边框属于同一体系？
5. 是否真的在解释内容，而不是把空白填满？
6. 静态产物是否不依赖外部脚本、字体或 CDN？
