# oil-ppt 演进规范

## 北极星

oil-ppt 以一张真实 HTML 页面作为最小创作、修改和验证单位。弱模型有成熟组件可以依靠，强模型可以突破组件自由设计；页面始终可见、可改、可验证，局部修改不牵动整套演示。

评估任何能力时检查六点：

1. 修改一页是否只需要读取和修改一页。
2. 模型编辑的源码是否直接对应浏览器真实结果。
3. 弱模型是否能从 starter 开始并在少量修复内通过检查。
4. 新构图是否无需修改程序或注册页面字段。
5. 常见设计是否能通过成熟 HTML 组件快速完成。
6. 预览、检查和构建是否永远不覆盖页面源码。

## 职责边界

模型负责语义与表达：受众、场景、叙事、页面数量、页面顺序、核心观点、素材角色、DOM、局部 CSS 和具体构图。

程序负责基础设施与可验证结果：1920×1080 舞台、等比缩放、安全区、全局 token、导航、项目顺序、资源路径、静态检查、浏览器检查、素材内联、确认状态、最终构建与导出报告。

用户负责确认创作方向、事实、素材和正式预览。大纲是参考，不是成品合同；页面制作过程中可以自然偏离。

## 页面与组件

- `slides/<id>.html` 是该页文案、DOM、局部 CSS 与素材引用的唯一事实来源。
- 页面是完整、可单独打开的 HTML 文档，并通过稳定 marker 暴露构建区域。
- 页面 CSS 必须以自己的 `.s-<id>` 命名空间隔离，不得修改 runtime 控制层。
- 组件提供可组合的 HTML/CSS 默认表现，不拥有页面内容，不规定字段数量，不决定页面轮廓。
- starter 是复制一次的示例；复制后页面可以任意修改，也不再与 starter 比较。
- 数据图表可以使用真实 JSON/CSV 数据，但数据格式不能成为页面布局描述。

## 面向不同能力的模型

只维护一条渐进式工作流：starter → 组合组件 → 修改局部 DOM/CSS → 完全自定义页面。自由度按页面决定，不按整套演示或模型标签决定。

弱模型接口必须返回一个页面路径、必要上下文、具体 selector、错误原因与下一条命令。不要要求它同时同步多个内容副本。强模型只要遵守项目边界和质量门禁，就可以自由改变页面结构。

## 视觉原则

- 一页只表达一个主要判断，优先用面积、位置、底色与留白建立层级。
- 真实截图、数据、材料和界面保持保真，不让图片模型重画事实证据。
- 流程、关系、结构与数据优先使用 HTML/CSS/SVG。
- 全局配色、字体、圆角与间距优先使用 runtime token。
- 内容少时放大核心关系；内容多时拆页或重组，不无限缩字。
- 1920×1080 舞台上的普通正文以 28–32px 为默认范围，24px 是解释性文字的阻塞下限；图注、来源、表头与短标签最低 20px，只有文字元素自身显式声明 `data-microcopy="index"` 或 `data-microcopy="meta"` 的短编号与辅助元数据可以低至 18px。
- 装饰浅、少、局部；不依赖阴影、嵌套外框或无意义细线制造层次。
- 默认画布是暖白、局部淡网格和无边框静面；默认 `grid-fade`，只有页面明确选择时才使用 uniform `grid-full`。媒体保持本地保真，装饰只在一个主要表面使用 dots、ring 或简单几何之一。
- 正常 8–10 页使用至少四类构图（聚焦、证据/媒体、比较/特征、顺序/系统、数据），以 76–96px 主标题、28–32px 正文和充分呼吸空间建立节奏；不要把每页变成同一种卡片墙、厚描边/阴影、深色终端背景或满页装饰。
- 默认视觉是轻盈的无边框静面：用面积、位置、柔和底色与留白建立层级；需要边界时才显式选择细线或强描边。
- 清脆感主要来自圆角几何，不靠加粗描边；技术方向也不等于黑黄工业风。默认一页最多一个主深色面，避免嵌套或重复外框。
- 内容放不下就拆页或重组，不能用缩小文字或等权卡片墙解决。2px 深色描边是有意的例外，不是默认语言。
- 重复单元的载荷随数量下降：2–3 个可以承载标题与解释，4 个及以上只承载编号或时间、标题和一句短解释；重复的第二层信息必须合并、聚焦或拆页。
- 清爽不是把内容压成顶部窄条。主要关系应使用舞台中部与足够的垂直空间，留白围绕关系分布，避免上半页拥挤而下半页空置。
- 16:9 页面不针对设备比例重排；runtime 等比缩放并居中。

## 检查边界

结构损坏、路径逃逸、远程资源、脚本、CSS 污染、素材损坏、文字溢出、内容越界、最终滚动、低于字号下限和可确定纯色背景上的文字对比度不足属于阻塞问题。浏览器检查必须临时显示并测量整套演示中的每一页，不能只检查当前页。密度、节奏和非常规构图属于建议，除非已经客观不可读。用户正式预览确认是视觉接受门槛。

## 变更流程

1. 说明缺少的是模型表达能力、通用组件、基础设施还是质量检查。
2. 能被所有页面稳定复用且客观验证的能力放入 runtime 或程序；只服务某页表达的能力留在页面。
3. 新组件先提供通用 HTML/CSS 示例，再用无业务依赖内容验证。
4. 检查单页原始尺寸、聚合预览、最终构建、非 16:9 容器和移动端控制界面。
5. 对高风险变更验证 source hash，证明预览与构建没有改写页面。
6. 保持单一、清楚的创作路径，删除重复分支和重复说明。

方向是语义简报与 deck-level preset，只推荐 palette、typography、shape，不增加页面 schema 或渲染分支。starter 是一次性复制的独立 HTML。背景、媒体、表面 craft 和关系节点只提供 CSS/HTML 原语，不登记 page schema、模板 registry、renderer branch 或兼容迁移。`style_advice` 只从真实页面给出保守、非阻塞的构图提示，绝不进入质量门禁、修复逻辑或工作流下一步；三个及以上装饰表面才提示，单个或两个有意装饰不提示。

## 合并门槛

- 弱模型通过统一入口发现 starter 和组件。
- 强模型能在不修改程序的情况下交付自定义页面。
- 单页问题只返回单页文件和具体 selector。
- 页面在预览和构建前后字节保持不变。
- 所有资源离线可用，页面与最终成品无溢出或滚动。
- 组件和测试使用通用内容，没有项目业务依赖。
- HTML、PPTX 覆盖率报告和安装包完整性检查通过。
- Skill 没有重复程序自动完成的内部步骤。
